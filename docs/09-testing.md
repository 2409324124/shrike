# 09 · Testing and evals

## Levels

| Level | Tool | What |
|---|---|---|
| Unit | `node:test` | One runnable check per non-trivial module (list below) |
| Integration | `node:test` + fixtures | Launch a fixture with node-agent, fire requests, assert on the DebugEvent tree |
| Desktop e2e | Playwright `_electron` | The killer demo end to end in the real app (`apps/desktop/e2e`: `demo`, `shop` (multi-process places, cache, fork, Stripe refusal), `big-app` (one Place order trip: 60+ functions in 30+ files across 8 services, queue, 3 caches, 3 Postgres, SQLite, Stripe and email doubles, CRON; fork, N+1 coil, backoff polls, snap at `totals.ts:25`; the Files view on it; the one-line fix turns it green), `api-only` (no page; explorer, curl and cron callers), `power` (point mode, drag to Ask, slash palette, quick open, issue copy, status strip), `inspector` (place inspector on todo-app and shop-app copies, offset ports); `branches` (C1–C5, C7: fork from FOUND IT and a step, map, Compare, aside, Bring it back; main's session file unchanged) `xray` (X1–X7: activity, file chips, thinking, tokens, context map adds up to the ring, race cards) and `chains` (P1–P5: two prompts queued while a run works fire in order in the same session; a critique of 5 polishes, then stops when it passes or at the round limit; a failed run takes the failure branch; save as chain; a scheduled prompt fires; the fake critic scores from `FAKE_CRITIQUE_SCORES`, `FAKE_CLAUDE_FAIL` fails a run) and `options` (M1 to M6: Show me options on the composer, three mockup cards in sandboxed iframes, enlarge and arrows, More like this on B, combine B2 + C across rounds, approve, the approved mockup beside the patch, Apply, design-taste learned into the project; `fake-options.mjs` plays it for real over the MCP tools) and `themes-composer` (Z, Q: ask from the docked composer, the conversation shows the ask, the answer and folded steps, `/` commands and `@` files, all six themes restyle the root and code colours, Match system follows a light or dark system, the pick survives a relaunch) on a recorded stream (`fake-claude.mjs` via `SHRIKE_CLAUDE_BIN`); `agent` and `agent-surface` need `SHRIKE_E2E_AGENT=1`). `SHRIKE_OPEN_FOLDER` stands in for the folder picker |
| Agent evals | `scripts/eval` runner | Bug corpus, scored |
| Perf | Integration harness | Overhead and event volume budgets |

**Headed by default, without stealing focus:** test windows appear (so runs can be watched) via `showInactive`, never take keyboard focus, and never send notifications. `SHRIKE_HEADLESS=1` hides everything (no window, no Dock icon) for runs that must stay off screen (`apps/desktop/src/main/headless.ts`).

## Agent eval corpus (`fixtures/bugs`)

Each bug is a folder with a patch on top of a fixture, the user's complaint in plain words, the expected root-cause `file:line`, and a scenario that fails before the fix and passes after.

```
fixtures/bugs/001-wrong-field-name/
├── bug.patch          # applied to fixtures/todo-app
├── complaint.txt      # "When I click Add Todo nothing shows up"
├── expected.json      # { "file": "server/todos.controller.ts", "line": 18, "category": "contract-mismatch" }
└── scenario.json      # steps + expect
```

Starting set (15 bugs, covering what vibe-coded apps actually break on):

| # | Bug | Category |
|---|---|---|
| 001 | Backend reads `req.body.user`, frontend sends `userId` | contract mismatch |
| 002 | Missing `await` on a DB call; response sent before save | async |
| 003 | Frontend calls `/api/todo` but route is `/api/todos` (404) | routing |
| 004 | Auth header never attached after login (token saved under a different key) | auth |
| 005 | CORS: server allows `localhost:3000`, app runs on `5173` | config |
| 006 | Required env var missing, server throws on first request | config |
| 007 | Frontend ignores non-2xx; shows success on a 500 | error handling |
| 008 | Server catches error and returns 200 with `{ error }` | swallowed error |
| 009 | Stale state: list doesn't refresh after create | frontend state |
| 010 | Pagination off-by-one skips the first item | logic |

### Scoring

| Metric | Definition | Beta target |
|---|---|---|
| Localisation | Agent's top finding cites the expected file, within ±3 lines | ≥ 80% |
| Explanation | LLM-judge + human spot check: correct cause, plain language | ≥ 80% |
| Verified fix | Proposed patch, applied automatically in eval, makes the scenario pass and breaks no other fixture scenario | ≥ 60% |
| Honesty | No "Observed" claim that the recording contradicts | 100% |
| Steps / cost / time | Median per run | track, no target yet |

Run the eval per brain (Claude Code, built-in, Codex, OpenCode) and record results in `fixtures/bugs/RESULTS.md` with the date, brain and model.
